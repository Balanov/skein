THE ACCEPTANCE PATH

The stop is enforced where results are accepted.

A stop command ends the processes, but the decisive check happens at acceptance: is this result still allowed to count. Skein checks the stop flag and the result's epoch before releasing dependents.

01 / STOP

Persist the stop first.

The first stop wins. Repeated stops do not advance the epoch again.

02 / FENCE

Reject stale work at acceptance.

A task can finish after the stop. Its old-epoch result still cannot release dependents.

03 / EXIT

Terminate the tracked process tree.

Windows uses tree termination; Linux and macOS use process groups. Detached and remote work remain outside this guarantee.

if scheduler.stopped.Load() ||
    !LeaseValid(execution.lease, scheduler.epoch) ||
    errors.Is(execution.err, ErrStopped) {
    scheduler.finish(state, Stopped, ErrStopped)
    return // no dependent is released
}

state.result.OutputPath = execution.output
scheduler.finish(state, Succeeded, nil)
for _, child := range scheduler.dependents[execution.id] {
    state := scheduler.tasks[child]
    state.remaining--
    if state.remaining == 0 {
        scheduler.ready <- child
    }
}
