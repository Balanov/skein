THE ACCEPTANCE PATH

The stop is enforced where results are accepted.

Cancellation asks work to end. The acceptance check decides whether its output may still change the run. Skein checks both the stop state and the result’s epoch before releasing dependents.

01 / STOP

Persist the stop before waiting for workers.

The first stop wins. Concurrent and repeated stops do not advance the epoch again.

02 / FENCE

Reject old work at the acceptance boundary.

A worker can return after cancellation. Its old-epoch output still cannot release a dependent task.

03 / EXIT

Terminate the tracked process tree.

Windows uses tree termination; Unix uses process groups. Detached and remote work remain outside this guarantee.

if scheduler.stopped.Load() ||
    !LeaseValid(execution.lease, scheduler.epoch) ||
    errors.Is(execution.err, ErrStopped) {
    scheduler.finish(state, Stopped, ErrStopped)
    return // no dependent is released
}

state.result.OutputPath = execution.output
scheduler.finish(state, Succeeded, nil)
for _, child := range scheduler.dependents[execution.id] {
    state := scheduler.tasks[child]
    state.remaining--
    if state.remaining == 0 {
        scheduler.ready <- child
    }
}
